# VIRTUALKHEL — Game Constellation

The universe of games, connected. VIRTUALKHEL turns 231 well-known video games into an interactive, navigable 3D galaxy and recommends games with a **deterministic, explainable similarity engine** — no LLM, no database, no paid service.

- **Next.js 15 (App Router) · TypeScript strict · React 19 · Tailwind CSS 4**
- **Three.js + React Three Fiber** for the galaxy, **GSAP ScrollTrigger** for the scroll journey
- Deploys to **Vercel** with zero configuration and zero environment variables

```bash
pnpm install
pnpm dev          # http://localhost:3000
pnpm check        # dataset validation + engine invariants
pnpm lint && pnpm build
```

This project uses **pnpm** (pinned via `packageManager`); `package-lock.json` is gitignored so npm and pnpm lockfiles cannot drift apart.

## What you get

| | |
|---|---|
| **Cinematic journey** | Six scroll stages — AWAKEN, DESCEND, DISCOVER, LOCK ON, CONNECT, YOUR UNIVERSE — where camera, copy, tint and highlighted nodes are choreographed together. No pinned sections, normal scrolling is never trapped. |
| **Explorer** | Orbit / zoom / pan, title search, genre + platform filters, hover cards, click-to-select, camera fly-to, highlighted connection paths, reset camera. |
| **Taste Reactor** | Choose three favourites → a weighted profile → every other game ranked, with the reasons. Matches light up in the galaxy. |
| **Accessible alternative** | A full index list grouped by genre, a keyboard-operable canvas (←/→ move, ↑ strongest link, ↓ back, R reset, +/- zoom, `/` search) and a live region announcing selection. |
| **Graceful degradation** | No WebGL → the explorer UI still works. `prefers-reduced-motion` → no drift, no scrubbing, instant camera cuts. Small / touch screens → fewer particles, lower DPR, stage-snapping instead of scrubbing. |

Skip the intro at any time: the first focusable element is a skip link, and the hero has a **Skip intro** button.

## Game DNA engine

[`lib/similarity.ts`](lib/similarity.ts) is the only place a score is computed.

- Each game becomes weighted feature sets per category: genre (primary ×2, secondary ×1), mechanics, setting, narrative, combat, perspective, aesthetic, play mode, platforms, developer, publisher, franchise and release era.
- A **taste profile** is the average of its games' feature sets (a single game is a profile of one), so pairwise similarity and the Taste Reactor use *the same formula*.
- Set categories use weighted Jaccard; developer / publisher / franchise are bonus-only; era decays linearly over 20 years.
- **Only supported fields are scored.** Optional categories count only when both sides actually carry data — an absent tag is never treated as a match or a mismatch — and no numeric gameplay "stats" are invented from titles or marketing copy.
- Every recommendation carries its strongest shared attributes ([`lib/recommendations.ts`](lib/recommendations.ts)).
- Pathfinding between two games uses Dijkstra over the graph ([`lib/graph.ts`](lib/graph.ts)).

`pnpm check` asserts the invariants: symmetry, bounds, bit-for-bit deterministic layout, no duplicate edges, sorted/explained/deterministic recommendations, path existence.

## Data & provenance

Games are rendered as a neon night city: each game is a lit tower in its genre district, linked by cables, with roads, street lamps, houses, parks and a central pagoda built deterministically around them ([`lib/city-plan.ts`](lib/city-plan.ts)).

`data/games.json` is **hand-curated** (generated by [`scripts/build-data.mjs`](scripts/build-data.mjs), which validates every row against a closed vocabulary). Year, developers, publisher and platform families are public release facts; tags are *editorial* labels from a fixed 139-term vocabulary ([`data/vocabulary.json`](data/vocabulary.json)). Each game records its provenance. Titles that were announced but not confirmed released at curation time carry `status: "upcoming"`, say so in the UI, and record that their year/developer/publisher come from the announcement; where a developer could not be verified the list is left **empty** rather than guessed. Curated relationships ([`data/relationships.json`](data/relationships.json)) each cite a reason.

Cover art is intentionally **not bundled** — publisher artwork is not freely licensed. Instead, the detail panel can fetch an optional public summary on demand:

- `GET /api/enrich?id=<game-id>` → Wikipedia REST summary (CC BY-SA 4.0) + Wikidata official website / Commons image (CC0 data; the Commons file page is linked for author & licence). Accepts only ids from the bundled dataset (no open proxy), 4.5 s timeout, 24 h cache, and every upstream failure degrades to `status: "unavailable"`.
- `GET /api/games?genre=&platform=&q=&limit=&offset=` and `GET /api/search?q=&limit=` expose the bundled dataset with validated, bounded inputs and CDN caching.

The core experience never calls an external service. No API keys are required, so there is no `.env.example`.

To add games: append rows to `ROWS` in `scripts/build-data.mjs`, run `pnpm build-data && pnpm check`.

## Architecture

```
app/                      page, layout, route handlers (games, search, enrich)
components/galaxy/        GalaxyCanvas (owns <canvas>), GalaxyScene (director, picker, labels),
                          City (instanced towers + ground), Streets (roads, lamps, houses, parks, pagoda),
                          GameNode (1 draw call for all beacons), ConnectionLines, Backdrop, shaders
components/journey/       ScrollExperience (mode + loading), JourneyOverlay (GSAP), SceneSection
components/game/          GameDetailPanel, GameSearch (ARIA combobox), GameIndex, RelatedGames
components/reactor/       TasteReactor, TasteProfile (radar instrument)
components/ui/            ExploreHud, FilterPanel
lib/                      similarity, graph, galaxy-layout, city-plan, arc, recommendations, data-validation,
                          scene-targets (state → visuals), store (vanilla external store)
data/                     games.json, relationships.json, vocabulary.json
```

Data, algorithms, rendering and UI state stay separate: `lib/` has no React; rendering reads state through a tiny external store and mutable refs.

## Performance notes

- The whole 3D stack is a dynamically imported client chunk (`ssr: false`); the hero text is server-rendered.
- Background stars, nebula sprites and all 165 nodes are **batched point sprites** (3 draw calls); edges are 2 `LineSegments`, highlights 1 more. No per-node React components.
- The render loop mutates typed arrays and DOM transforms directly — React never re-renders per frame or on hover.
- The similarity matrix is computed in yielding chunks after first paint, so scrolling never blocks.
- DPR is capped (1.25 on small/low-core devices, 1.75 otherwise) and drops to 1 if `PerformanceMonitor` detects sustained slow frames; rAF stops in hidden tabs; all GPU resources are disposed on unmount.

## Deploying to Vercel

Import the repo in Vercel — framework preset *Next.js*, no env vars, no build overrides. Vercel detects `pnpm-lock.yaml` and installs with pnpm. Route handlers run as serverless functions and never assume a writable filesystem.
